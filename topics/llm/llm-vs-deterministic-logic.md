# LLM과 결정론적 로직의 역할 분리

## 현재 판단

LLM은 의미 해석에 사용하고, 명확한 규칙 적용은 결정론적 코드에 맡기는 것이 안정적이다.

LLM이 잘할 수 있는 일과 일반 코드가 더 잘할 수 있는 일을 분리하면 시스템의 예측 가능성, 성능, 테스트 가능성을 높일 수 있다.

## LLM에 맡기기 적합한 영역

PlaNU에서 LLM이 의미를 가졌던 부분은 자연어 입력을 해석하거나, 사용자의 모호한 선호를 구조화하는 작업이었다.

예:

- "아침 수업은 싫고 금요일은 쉬고 싶어요"를 구조화된 조건으로 변환한다.
- "가능하면 수업을 몰아서 듣고 싶어요" 같은 모호한 선호를 Soft preference로 해석한다.

## 결정론적 로직에 맡기기 적합한 영역

PlaNU에서 다음 작업은 LLM보다 일반 프로그램으로 처리하는 편이 더 적절했다.

- 시간 충돌 검사
- 학점 범위 검사
- 학과별 수강 가능 여부
- 연속 수업 간 이동 가능 여부
- 후보 조합 생성
- 조건 만족 여부 검사
- 점수 계산

이런 작업은 규칙이 명확하고, 재현 가능해야 하며, 테스트 가능한 형태로 유지하는 것이 중요하다.

## 자연어 UI와 구조화 UI의 혼합

자연어 인터페이스가 있다고 해서 모든 입력을 자연어로 받을 필요는 없다.

현재 판단:

- 명확한 값은 form, select, upload 같은 구조화 UI로 받는다.
- 모호한 선호는 자연어로 받고 LLM이 구조화한다.
- 구조화된 조건을 실제 후보에 적용하는 단계는 결정론적 코드가 처리한다.

PlaNU에서는 학과 선택, 교양 영역 선택, 파일 업로드, 전공 과목 선택은 일반 UI가 더 적절할 수 있다고 판단했다. 반면 아침 수업 회피나 수업 몰아듣기 같은 선호는 자연어 입력이 유용했다.
