# 결정론적 규칙을 데이터로 분리하기

## 현재 판단

변경 가능하지만 결정론적인 비즈니스 규칙은 LLM prompt보다 별도의 데이터나 코드로 관리하는 것이 적절하다.

규칙을 prompt 안에 숨기면 변경, 테스트, 재현이 어려워질 수 있다. 반대로 규칙을 데이터나 코드로 분리하면 LLM의 의미 해석과 비즈니스 규칙 적용을 분리할 수 있다.

## PlaNU에서 관찰한 패턴

PlaNU에서는 학과별 수강 가능 여부, 캠퍼스 이동 가능 여부 등의 규칙을 JSON으로 분리했다.

이 선택의 장점:

- LLM prompt와 비즈니스 규칙 분리
- 규칙 변경 용이성
- 테스트 가능성
- 결과 재현 가능성
- LLM 환각과 무관한 동작

## 적용 기준

규칙이 다음 성격을 가진다면 prompt보다 데이터나 코드로 분리하는 편이 낫다.

- 입력과 출력의 관계가 명확하다.
- 같은 입력에 대해 같은 결과가 나와야 한다.
- 규칙 변경 이력이 관리되어야 한다.
- 테스트 케이스를 작성할 수 있다.
- LLM이 해석할 필요가 없는 결정론적 판단이다.
